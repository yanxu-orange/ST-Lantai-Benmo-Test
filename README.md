本轮修复

修复已复现的召回读取后遇到本地保存并发、因保存尚未确认而放弃注入的竞态。仅对已知本地进行中的保存等待完成，再核对原聊天、任务与来源，读取已提交记忆；保存失败、结果不明或等待超时仍明确失败，不绕过保存确认。累计实际等待预算 5 秒，构建前最多两次重建；构建／API 已开始后不自动重放付费请求。若任务最初就无法取得原始来源证明，仍保守停止。

召回、事件总结和古法总结在任务启动时固定本次提示词与配置；普通参数、提示词和受支持的模型／路由修改从下次任务生效，不因普通设置保存直接中断本次。总结写回仍保护已有手动编辑，不覆盖同一份成果的真实冲突。合并、关键词重建及跨刷新草稿恢复不在本轮改动范围。

安全与兼容边界

切换聊天、主动取消、功能关闭、来源编辑／删除／切换回复及真实写回冲突仍可停止任务；密钥撤销／替换、权限不明或保存失败同样失效，恢复旧密钥不会复活已撤销任务。密钥只保留在任务私有闭包，不进入诊断、配置证明、Worker 消息或持久化。

SillyTavern 自身全局 API 设置仍受严格校验，不能承诺所有宿主设置修改都继续。并发向量维护若换模型并替换缓存，旧查询安全停止，不混用模型向量；日历、日期与时间卡修改仍可能使本轮数据失效。

这是基于已发布安装树的定向修复，不是完整源码重新构建，也不是“酒馆自动重新生成剧情”的根因修复。保留 .20261021.3 的生成事件记录、导出入口及既有召回错误诊断。正式仓库及开发源码仓库未改动。

安装与反馈

更新前备份聊天、设置和扩展，停止生成；更新后刷新或重启，确认版本为 1.0.0-test.20261021.4，不同时启用两份兰台。旧0.4项目不做数据迁移。

之后正常使用即可，不需要专门增加付费生成。若再出现意外重新生成，请在刷新或关闭页面前，进入设置底部“关于兰台”→“导出生成诊断”。记录最多 300 条，仅在当前页面内存，刷新清空、不自动上传。如同时召回失败，请另保留“诊断：”后的标签。
